# ДурКер → Google Play: пошаговая инструкция

Приложение собирается в GitHub Actions (workflow «Android (AAB + APK)»), локально ничего ставить не нужно.
Всё, что нужно от вас, — шаги ниже. Тексты и графика уже готовы в `native/store/`.

## Что уже готово
- Оболочка Capacitor (`ru.durker.app`), код `js/native.js` (кнопка «Назад», статус-бар, «Позвать друга» со ссылкой на Play).
- Сборка AAB + отладочный APK: `.github/workflows/android.yml`.
- Политика конфиденциальности: `https://alic1035wizz.github.io/durocker/privacy.html`.
- Тексты карточки RU/EN: `native/store/listing.md`.
- Графика: `native/store/graphics/` (иконка 512, feature graphic 1024×500, скриншоты телефона/планшетов). Пересборка: `python3 native/store/make_graphics.py`.
- Ответы для форм «Безопасность данных» и «Возрастной рейтинг»: `native/store/data-safety.md`, `native/store/iarc.md`.

## Шаги для вас

### 1. Аккаунт разработчика (25 $, один раз)
1. https://play.google.com/console/signup → «Личный» аккаунт.
2. Оплатить 25 $ и пройти проверку личности (паспорт/права, адрес). Занимает от часа до нескольких дней.
3. Для **личных** аккаунтов, созданных после ноября 2023, перед публикацией обязательно закрытое тестирование: **минимум 12 тестировщиков, которые не выходят из теста 14 дней подряд**. Подберите друзей и попросите принять приглашение с их Gmail. (Организационному аккаунту это не нужно, но нужен D-U-N-S.)

### 2. Ключ подписи
Создайте один раз (Windows/Mac/Linux, нужен Java; можно в Android Studio или командой):
```
keytool -genkeypair -v -keystore release.keystore -alias durker -keyalg RSA -keysize 2048 -validity 10000
```
Запомните пароль и **сохраните файл в надёжном месте** — потеряете, не сможете обновлять игру (если включена подпись Play App Signing, можно восстановить через поддержку, но это долго).

Затем в GitHub: Settings → Secrets and variables → Actions → New repository secret:
| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.keystore` (на Mac: `base64 -i release.keystore`) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `durker` |
| `ANDROID_KEY_PASSWORD` | пароль ключа (если такой же — можно пропустить) |

Пароли и файл ключа мне присылать не нужно и нельзя.

### 3. Сборка
GitHub → Actions → «Android (AAB + APK)» → Run workflow. Через ~10 минут в артефакте будут:
- `durker-release-signed.aab` — это загружается в Play;
- `durker-debug.apk` — для проверки на своём телефоне (установите, откройте, проверьте кнопку «Назад», сеть, звук).
Без секретов получится `durker-release-UNSIGNED.aab` — его Play не примет.

### 4. Карточка приложения
Play Console → Создать приложение: название «ДурКер», язык по умолчанию — русский, «Игра», «Бесплатное».
- Тексты: из `native/store/listing.md`; графика: из `native/store/graphics/`.
- Политика конфиденциальности: ссылка выше.
- Контент приложения: «Безопасность данных» — `data-safety.md`; «Оценка контента» — `iarc.md`; целевая аудитория 13+ (лучше 16+); «Реклама: нет».
- Категория: Игры → Карточные. Контакт: ваша почта.

### 5. Закрытое тестирование → публикация
1. Тестирование → Закрытое → создать трек, загрузить `durker-release-signed.aab`, добавить список e-mail тестировщиков, отправить на проверку.
2. Тестировщики принимают приглашение по ссылке и устанавливают игру. Ждать 14 дней.
3. После этого «Запросить доступ к рабочей версии» и опубликовать в Производственной среде. Проверка Google — от нескольких часов до нескольких дней.

## Что может пойти не так
- **Азартная тематика.** Игра не использует реальные деньги, но казино-тема и ставки фишками могут дать повышенный рейтинг. Отвечайте в анкете честно (см. `iarc.md`). Не подключайте покупки фишек за деньги — это превратит приложение в симулятор азартных игр с платными фишками и осложнит публикацию.
- **Первая сборка.** Шаг `cap add android` в CI ещё не прогонялся (в песочнице нет доступа к npm и Android SDK). Если сборка упадёт, пришлите лог шага — исправлю.
- **Онлайн.** Игра работает через публичный брокер MQTT; если брокеры недоступны, одиночный режим продолжит работать.
- **Версия.** `versionCode` берётся из номера запуска workflow, `versionName` — из `VERSION` в `js/rules.js`.
